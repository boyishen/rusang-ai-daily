10 月 26 日, 双 11 进入中局, 三条线给出同一个判断: AI 在电商侧已经跑出可归因的增量, 但入口正在收窄——平台与大商户开始用"许可、限额、逐单确认"决定谁能替用户下单; 企业侧 157 位技术负责人的调研则把 agent 规模化的瓶颈指向治理与上下文, 而不是模型能力。合起来: 能力不缺, 缺的是"可归因、可授权、可治理"这三件基础设施。

01 万相点睛中期成绩单: 10 月 15–20 日带来近 10 亿元额外成交, 新客点击率超 90%
据亿邦动力 10 月 23 日报道, 阿里妈妈万相点睛在双 11 期间(10 月 15–20 日)带来额外成交近 10 亿元, 新客点击率超过 90%。品牌样本给出了不同侧面的证据: ELLE 新客成交占比 60%、新访客点击率 70.5%; 小仙炖新客占比超 90%、ROI 提升 20%; 超级直播叠加万相点睛后成交增长 30%、预算增加 180%。启示: AI 定向第一次在大促里给出"可归因增量"的口径, 但新客占比高不等于复购与退货健康——下一步该用对照组验证"增量是不是真增量"。
02 代理购物转向"签约准入": 亚马逊封禁 Perplexity, Yelp 开收内容许可费
据亿邦动力 10 月 19 日梳理, 代理购物的入口正从"开放抓取"转向"签约准入": 亚马逊已封禁 Perplexity、Meta Muse、Grok、Dots 等 agent; Yelp 开始向 AI 公司收取内容许可费; Delta、JPMorgan、Schwab 等也在阻断第三方 agent 访问。另一边, Meta 与 Walmart、Gap、Sephora、Best Buy 建立官方合作, Shopify 向全量商家开放 agent 结账, Cloudflare 则提供 AI 爬虫拦截。启示: "谁能替用户下单"正由平台与大商户的许可协议决定; 做 agent 或联盟侧, 尽早拿到官方授权与结算通道, 比抢流量入口更关键。
03 企业 agent 调研: 75% 的团队卡在 10–15 个 agent, 34% 的上线 agent 无人复核
据亿邦动力 10 月 21 日报道, 一份覆盖 157 位企业技术负责人的调研显示: 超过 75% 的团队在同时运行 10–15 个 agent 时遇到瓶颈; 34% 的上线 agent 没有人工复核; 只有 5% 的团队对 agent 做信任评估; 约 30% 出现过未经授权的数据访问。上下文对齐率从 30% 提升到 90% 后, 两个月又回落到 60%。启示: agent 规模化的真正门槛是权限、上下文与责任链的治理; 先把"谁能改、谁能看、出错谁担"写清楚, 再谈扩量。

双 11 中期实测: AI 定向带来近 10 亿元额外成交, 新客点击率超 90%

10 月 15–20 日, 阿里妈妈万相点睛在双 11 期间带来额外成交近 10 亿元, 新客点击率超过 90%。三个品牌样本给出了不同侧面的证据: ELLE 新客成交占比 60%, 小仙炖 ROI 提升 20%, 超级直播叠加后成交增长 30%。

  • 做法: 用 AI 定向圈出高潜新客, 再把直播、补贴与素材按人群动态组合, 而不是全量统一投放
  • 成效: 额外成交近 10 亿元; ELLE 新访客点击率 70.5%; 超级直播叠加后预算增加 180%、成交 +30%
  • 卡点: 新客占比高不等于复购健康, 退货率与增量归因尚未披露, 需要对照组才能确认"真增量"
  • 启示: 把 AI 定向当成一条可 A/B 的渠道来跑, 先小流量验证 ROI, 再决定是否放大预算

→ 案例报告: 当 AI 定向能给出"额外成交"口径, 大促投放就从"抢曝光"变成"算增量"; 但别把平台口径当最终结论, 自己补一组对照, 才知道预算该加在哪个环节。

落地实践8

157 位技术负责人调研: 75% 的团队卡在 10–15 个 agent, 34% 无人复核

一份覆盖 157 位企业技术负责人的调研显示, agent 规模化的第一道坎不是模型能力, 而是治理: 超过 75% 的团队在同时运行 10–15 个 agent 时遇到瓶颈, 34% 的上线 agent 没有人工复核。更刺眼的是, 只有 5% 的团队对 agent 做信任评估, 约 30% 出现过越权数据访问。

  • 卡点: agent 数量一多, 权限、上下文与责任链同时失控, 出错后很难定位是谁的问题
  • 做法: 先做上下文对齐与权限隔离; 调研中把上下文对齐率从 30% 提到 90% 的团队, 两个月后仍回落到 60%
  • 教训: 34% 的 agent 无人复核、仅 5% 做信任评估, 意味着大多数团队在用"上线速度"换"事故概率"
  • 启示: 扩量前先回答三个问题——谁能改、谁能看、出错谁担; 治理规则跑通, 再从 10 个扩到 50 个

→ 避坑清单: 别把 agent 数量当成数字化进度; 没有人工复核、没有权限边界、没有信任评估的"三无"上线, 规模越大, 事故面越大。

券商研报从 2–3 天压到几分钟: 企业微信里的"数字同事"跑通三类场景

腾讯 WorkBuddy 与企业微信打通后, 在券商、制造、零售三类企业里跑出可复用的场景: 券商研究报告的初稿周期从 2–3 天缩短到几分钟, 制造企业用它做模具核价, 零售团队用它做盘客、锁客与 CRM 跟进。它们的共同点不是"更聪明的模型", 而是把 agent 放进了员工每天已经在用的工作流。

  • 做法: 不另开入口, 把 agent 嵌进企业微信的聊天与群工作流, 让"调用 AI"变成一次 @
  • 成效: 券商研报初稿 2–3 天→几分钟; 制造企业模具核价、零售盘客/锁客/CRM 跟进均可复用
  • 卡点: 企业数据权限、口径统一与历史资料治理是前置, 资料不结构化, agent 也读不懂
  • 启示: 先找"高频、有模板、可验收"的岗位切入, 比做一个全员通用的 AI 助手更容易跑出 ROI

→ 落地路径: 当 agent 的入口是员工每天必开的 IM, 采用成本被压到最低; 对推 AI 落地的团队, "少一个 App、少一次跳转"往往比"多一个功能"更能决定用不用起来。

星巴克中国"消费入座"背后: 客单价连降, 但交易次数转正

arXiv: 同一个模型换个"外壳"就差很多, agent 评测该把模型和 harness 分开算

论文《When Agents Fail: Model or Harness—Who's to Blame?》用 4 个通用 harness(OpenCode、Codex CLI、Pi CLI、DeepAgents)搭配 4 个核心模型, 在 6 类基准上跑了 111 种设置、52168 条轨迹。结论: harness 排名会随模型与基准变化, 任务分数与"有效完成率"可能指向不同组合; OpenCode 的跨模型表现第一, DeepSeek V4 Flash Preview 的有效完成率最稳。启示: 内部评测若不拆开"模型"和"工具壳", 很容易把 harness 的问题算到模型头上。

arXiv: 企业 RAG 的胜负手是"先组织再检索", 241 个仓库里定位 100+ 缺陷

论文《Reimagining Enterprise RAG for Multi-Agent Systems》用 7 个 agent 的反向工程流水线, 处理 18 个服务、241 个仓库, 产出数千个描述范围、旅程、规则与验收标准的 artifact。由于 offer、eligibility 等实体在不同服务里"同名不同义", 扁平向量检索会把错误服务的规则以高相似度召回; 作者把本体放在 artifact 层, 用来源元数据先消歧再检索, 一周内建成, 支撑了 100+ 生产缺陷的根因分析与 35 次发布回归的归因。启示: 企业知识库别急着调向量模型, 先把"这条知识来自哪个服务、哪个版本"变成结构化字段。

arXiv: GUI agent 新基准 IGG——人 94.6%, GPT-5.5 79.4%, 最强开源 VLM 仅 31.6%

IGG 基准包含 601 个任务、16 个可控 GUI 环境、7 类"可见性约束": 目标可能在屏幕外、悬停后才出现、被遮挡或延迟可点。人类准确率 94.6%, GPT-5.5 79.4%, 最强开源 VLM 只有 31.6%。关键实验: 告诉 Qwen3-VL 该做什么交互, 准确率只从 30.8% 升到 33.9%; 直接替它完成交互, 则升到 81.9%——瓶颈在"把目标弄出来"的执行, 不在"看见后点中"。启示: 做手机、桌面 agent, 滚动、等待、拖拽这些"让目标出现"的动作策略, 比换更强的视觉模型更值得投入。
