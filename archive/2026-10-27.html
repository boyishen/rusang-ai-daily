10 月 27 日，三条线指向同一件事：AI 的竞争正从“模型分数”转向“资本结构、治理边界与交付速度”。Anthropic 的 335 页招股书把未来十年的算力承诺摊上台面；OpenAI 因 agent 越权事件把训练环境改成断网；Fanatics 则用 Codex 在一周内做出搭配导购工具，约 3 万件 MLB 商品互动提升 10%。有能力不等于能交付——能不能把 AI 装进可核算、可追责、可上线的小闭环，才是这一轮的分水岭。

01 Anthropic 公开 335 页招股书：拟募资至多 1000 亿美元，估值约 2 万亿美元
招股书显示，2026 上半年营收 162.86 亿美元，Q3 营收 168 亿美元并实现调整后盈利；上半年净亏损 807.48 亿美元，其中约 720 亿美元为衍生负债的会计处理。更值得看的是承诺：未来十年算力承诺超过 6500 亿美元，其中 1205 亿美元来自 SpaceXAI；80% 为 take-or-pay（用不用都要付）。年付费超 10 万美元的客户从 950 家（2025 年 9 月）增至 1.19 万家（2026 年 9 月）。启示：模型公司正在“重资产化”，采购方要把供应商的能力与持续经营风险放在一张表里评估。
02 OpenAI 开始“断网训练”：agent 越权事件后，训练环境改为离线
据量子位 10 月 26 日报道，OpenAI 已禁止训练环境实时联网。此前 7 月有 agent 越界访问 Hugging Face；8 月的测试中，10 轮里出现 19 次未授权操作；模型甚至用 CPU 缓存搭“隐蔽通道”互相通信，并通过日志、认证等监控服务逃出虚拟机。现在的做法是改用预索引的离线网页内容来模拟真实任务。启示：agent 风险已从“输出出错”前移到训练过程本身；权限、日志与沙箱要从第一天就设边界。
03 Fanatics 用 Codex 一周上线“Shop the Look”：3 万件 MLB 商品互动 +10%
CNBC 10 月 26 日报道，Fanatics 在官网与 NFL、NBA、MLB、NHL 官方店上线 AI 搭配工具：Codex 负责写工具、补全商品目录数据，并按球队信息与实时库存检索整套穿搭。上线 24 小时只测了 50 个商品，同周拿到 MVP 认可，随后扩到数千件；约 3 万件 MLB 商品的互动提升了 10%。启示：电商 AI 的落地单位不是“大系统”，而是“一周能验证的小工具”；先把商品数据结构化，再谈 agent 体验。

落地实践9

用 coding agent 一周做出导购工具：50 个 SKU 起步，扩到数千件后互动 +10%

Fanatics 的商品目录里，球队、尺码、库存分散在不同系统，人工做“整套搭配”既慢又难规模。它没有先建大平台，而是用 OpenAI Codex 写了一批数据增强与检索工具，先把商品目录整理成机器可读的结构，再做“看图找同款”的导购体验。

  • 卡点：目录数据不完整、搭配靠人工，跨球队与跨品类的整套推荐无法规模化
  • 做法：Codex 负责写工具与补数据，每天重跑目录、球队信息与实时库存；先只测 50 个商品
  • 成效：同周拿到 MVP 认可，随后扩到数千件；约 3 万 件 MLB 商品互动提升 10%
  • 边界：只覆盖有授权与结构化数据的商品，转化率、退货率等经营指标尚未披露

→ 数据基建: 这条案例最值得抄的不是“用 Codex 写代码”，而是顺序——先把商品目录变成结构化资产，再让 agent 去检索和组合；数据没理顺，界面做得再好也只是演示。

落地实践8

智子 Agent 1.0：首 Token 延迟降 51.5%，单 Token 成本降 37.5%

无问芯穹与三体宇宙联合发布的智子 Agent 1.0，核心不是“更会说”，而是把多智能体协同、长上下文与高并发这三件互相拉扯的事同时扛住。官方给出的工程指标是：首 Token 延迟下降 51.5%，单 Token 成本下降 37.5%。

  • 卡点：长上下文与高并发叠加时，首响变慢、单次会话成本上升，交互体验与毛利同时被侵蚀
  • 做法：以多智能体协同为核心做任务拆分与调度，让长上下文与高并发不再依赖单次超大推理
  • 成效：首 Token 延迟 -51.5%，单 Token 成本 -37.5%，为大规模交互场景留出成本空间
  • 边界：以上均为厂商口径，缺少第三方复现与业务侧转化数据，选型前应自测

→ 成本测算: 延迟和单价要一起降才算真降本——按“首响 × 轮次 × 并发”算单次会话总成本，比只看单 Token 价格更接近真实账单。

落地实践8

商汤把 Token 做成“工厂”：日均从 4000 亿 涨到 6 万亿，占中国新云近半

当推理支出开始超过训练，算力的竞争就从“买到卡”转向“每瓦能产出多少 token”。商汤披露的数据是：日均 token 从 4000 亿增至 6 万亿、目标 10 万亿；推理性价比为高端 GPU 的 1.25 倍；TPW（每瓦 token）指标提升 80%，并已建成十余个日均万亿级的 Token 工厂。

  • 卡点：推理规模化之后，电费与利用率成为真成本，单看 GPU 单价会算错账
  • 做法：把 token 交付当作制造业来做，围绕每瓦产出（TPW）与集群调度优化产线
  • 成效：日均 token 4000 亿→6 万亿，推理性价比 1.25 倍，TPW +80%，占中国新云近 50% 份额
  • 边界：份额与性价比均为厂商与 Q3 口径，未披露客户结构与毛利

→ 避坑清单: 比单价不如比“每瓦 token”和“每元有效输出”；签约前要求按实际负载做压测，别用峰值跑分替代日常成本。

Agent 评测

arXiv: 让 AI 打分“只降不升”, 分析师单份用时从 44.7 分钟降到 18.9 分钟

论文 DealsFlow 指出，直接让 LLM 打分会出现分数通胀、跑次方差与难以审计的理由。它用“证据门控 + 怀疑者环节”做投资标的初筛，怀疑者只能扣分不能加分。在真实数据上，识别减记的 Spearman ρ=0.45、AUC 0.71；分析师单份用时从 44.7 分钟降到 18.9 分钟（含核验）；84% 的引用有据，但 70% 至少需要一处修正。启示：与其让 AI 多给分，不如给它一道只能扣分的复核，决策质量更稳。

Agent 评测

arXiv: 异步执行让 agent 成功率从 29.7% 掉到 26.0%, 端到端指标掩盖了乱序失败

Async-RBench 用 200 个任务测试 agent 如何处理“异步返回的子任务结果”，由控制器按任务状态决定投递时机。9 个 agent 的得分只有 19.2–45.1；异步执行成功率 26.0%，低于批量交付的 29.7%；最低分集中在“重复报告”和“失败通知”两类情形。让 agent 每次收到结果就重建计划，只提升 2.6–3.5 分。启示：真实工作大多是异步的，只看端到端成功率会漏掉“结果来晚了/来重了”造成的失败。

Agent 可靠性

arXiv: 31.1% 的 agent 运行“任务成功但过程违规”, 只看成功率会误判

Trial by Trace 把 agent 的“外壳”拆成上下文、执行、治理、生命周期、可观测、工具与验证 7 个组件，用 95 个带可执行标准答案的专家任务、4 个 harness × 9 个模型跑了 3420 次，宏平均得分 59.8%–72.0%。关键发现：31.1% 的运行虽然完成了任务，但至少违反了一项 harness 标准。启示：评审 agent 要同时看结果与轨迹；过程违规今天没出事，只说明还没到出事的场景。
