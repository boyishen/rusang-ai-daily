01 能力账：1000 个智能体、30 小时完成费马大定理形式化，成本降至 1/3

03 治理账：OpenAI 部署“控制室”，35 秒内叫停失控智能体
OpenAI 上线“控制室”系统：智能体任务需先获得授权 ID，引擎在请求确认后才继续推理；一旦下达停止指令，系统拒绝后续输出，从收到指令到阻止任务的最长延迟为 35 秒，官方目标是把延迟压到 0。启示：Agent 落地的前提不是“更能干”，而是“能被随时叫停”。

案例报告9

蚂蚁灵波开源 LingBot-Touch：5000 小时触觉数据，26 项测试成功率提升 14—26 个百分点

蚂蚁灵波科技开源触觉基础模型 LingBot-Touch，基于近 5000 小时数据预训练，覆盖磁、视、压阻三类传感器；在 26 项真机测试中，任务成功率提升 14—26 个百分点。

  • 卡点：机器人“看得见”但“摸不准”，换物体、换材质就要重新示教，精细操作难复制
  • 做法：把触觉做成独立基础模型预训练，再以 Tiny/Small 两个尺寸适配不同算力
  • 成效：拧瓶盖成功率从 56.25% 提升到 90%；26 项测试全部提升 14—26 个百分点
  • 边界：仍是实验室真机数据，跨本体、跨场景的泛化需要更多现场样本

→ 案例报告: 可复用的不是某个传感器，而是“把一种模态做成基础模型”的路径——先有稳定表征，再谈跨本体迁移。

避坑清单9

OpenAI 部署“控制室”：35 秒内叫停失控智能体，目标把延迟压到 0

OpenAI 上线“控制室”系统，所有智能体任务需先获得授权 ID，引擎在请求确认后才继续推理；一旦下达停止指令，系统会拒绝后续输出，最长延迟 35 秒。

  • 卡点：Agent 一旦自主执行，风险不再是“说错话”，而是“停不下来”
  • 做法：中央服务统一授权、任务级 ID、停止即拒绝输出，把“刹车”放在推理入口而非末端
  • 成效：从收到停止指令到阻止任务，最长 35 秒；延迟主要来自缓存层
  • 边界：35 秒对高频交易、工业控制仍太长，官方称正努力缩短到 0 秒

→ 避坑清单: 上 Agent 前先设计“停机路径”：谁有权停、多久生效、停了之后状态怎么回滚；没有这三项，自动化越深，事故面越大。

多智能体

arXiv：并行小团队胜过 100 个独立智能体，等成本下赢过前沿模型一半任务

论文研究并行 agent 团队的测试时扩展：10 人小团队优于 100 个独立 agent 或更大的团队；在同等成本下，它在前沿模型能完成的一半任务上取得更好结果。启示：多 Agent 的关键是“团队结构 + 采样平衡”，不是简单堆数量。

人机委托

arXiv：调查 289 人、45 个用例——信任与省钱提高委托意愿，成就感下降则相反

论文基于 289 名受访者、45 个用例，研究人愿意把哪些任务交给 Agent：对系统的信任和节省成本会提高委托意愿，而降低“完成任务的满足感”会显著降低委托意愿；整体上，人们仍倾向保留人类监督。启示：自动化设计要给人留下“有意义的参与点”。
