落地实践9

李宁把 50 个 AI 智能体“编入组织”：年等效 46 万小时，约 220 名员工

李宁将 50 个 AI 智能体编入组织，覆盖设计、供应链与终端场景；官方口径年等效 46 万小时，约等于 220 名员工，其中数字店长占三分之二。

  • 卡点：AI 工具停在“个人提效”，没有进入岗位、流程与考核，规模一大就回到手工
  • 做法：把智能体按岗位编入组织，数字店长占 2/3，先跑设计、供应链、终端三类高频场景
  • 成效：50 个智能体、年等效 46 万小时、约 220 名员工的工作量
  • 边界：“等效人力”不等于裁员或替代，岗位职责、复核与责任归属仍需重写

→ 组织重构: 先把 Agent 当“岗位”而不是“工具”，再谈编制与考核；否则效率只停留在个人层面，组织不会真正变化。

AI 客服“承诺不算数”：2026 年投诉超 5300 条，中消协点名案例

“人民直击”调查显示，AI 客服的承诺与实际履约不一致：中消协披露案例中，AI 称报价含过户费，消费者实际仍被收取 1000 元；2026 年相关投诉超过 5300 条。

  • 卡点：AI 客服被当成“会说话的 FAQ”，没有权限、没有边界，也无人对承诺负责
  • 做法：律师明确“经营者部署的 AI 客服，其服务行为等同于经营者服务行为”
  • 成效：2026 年相关投诉超过 5300 条，中消协案例中单笔多收 1000 元
  • 边界：仅靠提示词约束不够，需要“不可承诺清单 + 人工兜底 + 全程留痕”

→ 避坑清单: 上线 AI 客服前先划三条线：不能承诺什么、什么必须转人工、每一句承诺由谁负责；否则省下的人工成本会变成投诉与赔付。

智能体运行

arXiv：给 Agent 看“已验证的运行时快照”，策略后悔值降低 96.9%

论文提出 Agent Harness Awareness：把工具调用时的运行时状态做成经过验证的遥测快照，再交给 Agent 决策；在工具使用任务上，策略后悔值降低 96.9%。启示：Agent 的“自我认知”不必靠更长的提示词，靠可验证的状态输入更便宜、更可靠。

代码验证

arXiv：99.1% 的验证通过率，只有 1.9% 真正绑定需求

论文《Verified but Vacuous》拆解 LLM 代码验证的三类失败面：验证器给出 99.1% 的接受率，但只有 1.9% 的通过结果真正绑定到规格说明。启示：把“测试通过”当成“需求满足”是危险的；验收要检查测试是否覆盖真实约束，而不是只看绿灯。
